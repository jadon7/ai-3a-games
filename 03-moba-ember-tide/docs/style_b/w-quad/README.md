## 四足的做法（第二批以后照着用的清单）

`<id>` 英雄名，`<old>` 旧的管线名（卡兹 `kaz`、托尔格 `turtle`、奥森 `stag`；野怪就是怪名），过程文件放 worktree 的 `art/style_b/<id>/`。
照着抄的例子：`art/style_b/kaz/`（腿用 dir、迈步站姿）、`art/style_b/torg/`（名字全乱、加记号骨骼、改 k）、`art/style_b/osen/`（最顺的一个）。

1. **Tripo 出模型**：设定图拷成 `ref.png`，`tripo_jobs.json` 写 `hero_<id>_b`（`face_limit` 40000、`detailed`），`tools/tripo_batch.py`，挪到 `art/style_b/<id>/raw.glb`，`tools/blender/views.py` 渲 6 个角度看。40 额度、3 分钟。
2. **绑骨**：`tools/tripo.py rig <task_id> --rig-type quadruped --out-format glb` → `tripo.py wait … --download art/style_b/<id>/tripo_rigged.glb`。25 额度、1 分钟。
3. **看骨架、找错绑**（最费眼的一步，10–20 分钟）：`V2R/scripts/blender/inspect_weights.py` + `art/hero/torg_turtle/draw_bones.py` 出三视图和每根骨骼管的范围（`inspect/weights.txt`）。
   - 骨骼名**不能信**，按“管哪块肉、在哪”认（托尔格的 `Head_*` 是左前腿）。
   - 每只都有错绑，专看三类：box 跨到另一侧的（右脚趾管着左脚）；尾巴、挂件（吊炉、钟、链子）绑到腿上的；硬壳（背甲、铁甲）绑到腿上的。可疑的再按骨骼列顶点分布（y 一段、左中右）确认。
4. **修错绑**：`rig/fix_weights.json`（`from`/`to`/`box`，坐标是 Blender 导入后的）→ `tools/retarget/quad_fix_weights.py`。只挪 `from` 那一份权重，别的不动。
5. **改成旧骨骼名**：`rig/rename.json`（新名 → 旧名，名字一样角色也一样的写进 `_keep`）→ `tools/retarget/quad_rename.py <fixed.glb> rename.json V2R/assets/model/<id>_b_rigged.glb V2R/assets/model/<old>_skeleton.json`。
   为什么要改名：时间表的 `points`、英雄代码里写死的骨骼（卡兹的前爪 `tripo0_Left_Limb_5`）都认旧名字，改了名它们一行都不用动，`case.json` 的 `map` 也就是“同名对同名”。新骨架多出来的碎骨头撞了旧名字的自动改成 `x::…`。
   节数对不上的（新的脖子三节、旧的一节）不硬改名，在 `case.json` 里用 `chains`。
6. **摆正**：`V2R/assets/model/<old>_rigmap.json` 抄一份成 `<id>_b_rigmap.json`，只改 `forward`（看 inspect 的坐标，三只都是 `[0,-1,0]`）、删掉新骨架里没有的骨骼和跟踪点；`prep_rig.py … <id>_b_rigged.glb <id>_b` 出 `V2R/assets/model/<id>_b.blend`。不训练、不出视频。
7. **缺的记号骨骼**（时间表 `points` 认的骨骼新骨架里没有时）：`tools/retarget/quad_add_marker.py` 在 `.blend` 里加一根同名、不带权重的骨骼（托尔格钟里的 `tripo::Spine_1`）。
8. **读骨架**：`dump_rig.py` 读 `<old>.blend` 和 `<id>_b.blend`；腿要用 `dir` 的话再跑 `tools/retarget/quad_tails.py`（把腿每节的尾巴指向下一节，两边方向才对得上）。
   3–8 步写成一个 `rig/make_rig.sh`，改了映射一条命令重来（30 秒）。
9. **`retarget/case.json`**：`map` 写成“同名对同名”的字典（再加上没改名但要跟着某根走的，如卡兹的侧脚趾），`chains`、`legs`（四条腿各三节，`src_end` 是旧的掌/跖）、`ground_chains`（脖子根 + 头），`src_timing` 指开工时拷的 `src_timing.json`，`game_h`、`src_game_h` **都写旧的身高**。
   - `mode`：先全 `delta`。新的静止站姿是迈步姿势（四条腿前后差 10 厘米以上，卡兹）时，腿的上几节改 `dir`（`mode_bones`）。两种都跑一遍，比“胯放低最多”和“身体最低”，挑小的（托尔格：dir 站着就要放低 3.4%，delta 1.3%）。
   - `k`：默认按胯高比；新模型的身子相对胯垂得更低（龟的背甲）时，R、死亡这类贴地的动作会插进地里，改小（托尔格 1.073 → 1.0）。
10. **套、量、看**：`run_case.py case.json retarget` →（跳起腾空的段 `art/style_b/quad/blend_air.py`）→（身子插进地里的段 `art/style_b/quad/lift_body.py`）→ `run_case.py … measure` → `table.py`；胯放低超过 3% 的段，查是哪条腿够不着、哪块插进地里；`run_case.py … render` 出拼图看完删 `retarget/render/`。两个后处理脚本是 `w-beast` 写的（原件主目录 `art/style_b/beasts/`），重跑 retarget 会覆盖，要重跑。
11. **出品**：`build.json`（creature_build 的，`name` 是 `<id>_b`，动作指 `retarget/motions/ik/`）+ `zsh art/style_b/quad/rebuild.sh <id> <名字> <look.height> <game_h> [runSpeed]`：creature_build → `tools/style_b/b_rename.mjs`（材质名改 `hero_b`，creature_build.py 没有 `body_material`）→ `strip_maps.mjs` → 时间表（`runSpeed` 乘 look.height / game_h）→ 名字是英雄 id 时出手机档。先用 `<id>_b` 进游戏看，定了再写正式的。
12. **进游戏看**：旧模型拷成 `<id>_v9`（提交前删）；`compare.mjs` 旧的要带 `look=` 把 `heroes/<id>.ts` 里新加的 `height`/`lift`/`sat` 退回去；
    - 个头：新模型的包围盒高常常变（耳簇、鹿角），按 `look.height` 补（卡兹 2.8 → 3.1）；
    - 颜色：近镜头对设定图量（`art/style_b/quad/colors.py`），太亮太灰就在 `look` 里给 `lift`、`sat`（托尔格 1.05 / 1.6，奥森 1.2 / 1.5）；
    - 显眼：`art/style_b/quad/pop_all.sh <输出> <id> <旧glb>:<身高[,look]> <新glb>:<身高>`（`play=0` 的网址一定带 `h=<id>`，不然用的是岚的 look）；个头一排：`art/style_b/quad/size.mjs`；跑步滑不滑：`art/style_b/quad/run_probe_tip.mjs`（`SK=<id>_b`）。

机器时间：一只从设定图到进游戏 15–25 分钟（Tripo 5 分钟、套动作和出拼图 3 分钟、出品 2 分钟）；人看和改：第一只（卡兹，连写工具）约 70 分钟，第二、三只各 20–30 分钟；证据和回归另算（这次机器负载 200 上下，无界面 Chrome 很慢）。Tripo 每只 65。

## 已知的坑（这次踩到的）

- **`run_case.py build` 的 runSpeed**：`game_h` 和 `src_game_h` 不一样时，量出来的比例本来就是按各自身高换算的，又乘了一遍 `game_h / src_game_h`。两个都写旧的身高，出品后再乘 新身高/旧身高（`art/style_b/quad/rebuild.sh` 里做了）。共用脚本没改。
- **四足跑步的 runSpeed 量不准**：源动作里卡兹左前脚 15 帧有 12 帧算“着地”，按贴地速度算出来的比例是 0.86（腿明明变长了）。卡兹最后按腿长比（1.075）定 10.5，游戏里量后脚滑得和旧的差不多（左后 −2.5、右后 −1.05 米/秒；旧的四只 −1 上下）。托尔格、奥森用量出来的比例（1.04、0.93），没在游戏里单独量。
- **`tools/blender/creature_build.py` 没有 `body_material`**，材质一律叫 `hero`，游戏认不出 B：出品后跑 `tools/style_b/b_rename.mjs`。（以后给 creature_build.py 加一个和 hero_build.py 一样的可选项更干净；这次没改共用脚本，免得和 `w-beast` 冲突。）
- **`tools/style_b/pop.py` 取英雄的窗口是给人形的**（140×200），四足会切掉身子：用 `art/style_b/quad/pop.py`（放宽到 320×240）。
- **对照旧模型时 `heroes/<id>.ts` 的 `look` 也作用在旧模型上**（`glb=<id>_v9` 只换模型），要在网址里用 `look=` 退回去。
- 机器上六个任务同时跑，无界面 Chrome 常常 90 秒都载不完（`pop.mjs` 超时），重跑一次就好。

1. **卡兹的毛色偏冷**：设定图是带一点暖紫的炭灰，游戏里是蓝灰（场景天光偏冷，`look` 只有提亮和饱和度，调不了色相）。在红土上反而更跳，没改。
2. **卡兹的跑步脚滑**：后脚着地时左后 −2.5、右后 −1.05 米/秒（旧的四只 −1 上下），左右不匀是源动作里就有的；前爪在游戏里量不准（爪尖的标记点在新骨架上放偏了），只看了后脚。托尔格、奥森的跑步没在游戏里量。
3. **发光**：卡兹面甲的熔岩红眼缝、奥森鹿角上的烛火在设定图里是亮的，游戏里不发光（游戏只认贴图里的青色当发光纹路，旧模型也一样）。托尔格的钟口和头盔圆窗是青色，发光正常，钟口亮得比设定图还猛一点。
4. **托尔格右前脚、奥森右前腿少一节**：新骨架里没有对应旧骨架的蹄骨/脚掌骨，那一节跟着上一节走（奥森右前蹄在跑、跪时不折），拼图里看不出来，游戏镜头里更看不出来。
5. **托尔格的出手点**：钟里加的记号骨骼位置是照旧模型“钟口往下 0.12、偏左 0.11”估的，技能特效从钟口出看着对，没有逐帧核。
6. **奥森的蜡烛**：Tripo 读出来了十几根，但形状比设定图糊，近看是一团团的蜡；游戏镜头里看不出。
7. **证据的先后**：奥森的个头、对局、手机图是 `look` 压亮度之前拍的（比最终的亮一点）；技能连拍、近镜头、显不显眼都是最终的。机器负载 200 上下时无界面 Chrome 很多次 90 秒载不完，没有全部重拍。
8. 骨骼改名以后旧的名字和新骨架的“角色”是我按位置认的，三只的映射都只在拼图和测试场里看过，没有一段一段在 Blender 里看蒙皮权重。
