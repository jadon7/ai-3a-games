# 地图和设计稿的差距：从哪来、怎么缩（第九轮 · 第 11 条）

用户原话：“当前的地图实现跟设计稿还是存在巨大的差距，判断一下差距来源于哪儿，你觉得能从什么层面优化”。这份只做判断和建议，没有改任何代码和资源。对比图都在这个目录里，左边是设计稿，右边是现在的地图，同一个位置、相近的机位。

（由 Opus 5.5 的 `map_gap` 任务写成；任务环境不让它写 .md 文件，报告全文由调度原样存进这里。）

## 一、结论（直说）

**差距主要来自三件事，按分量排：**

1. **光是平的。** 设计稿的明暗是“画出来的”：大片的树冠投影、暖色的阳光对冷色的阴影、墙脚和草根的暗部，整屏分成几大块亮和暗。
   - 现在只有一盏太阳加一盏很强的天光补光；地面贴图又被有意画成“没有投影、光照均匀”。所以整屏亮度差不多，阴影只有物件自己那一小条。
   - 量出来，设计稿整屏大块明暗的起伏约是现在的 2 倍（绿色一侧 0.10–0.12 对 0.04–0.05）。现在的细碎明暗却和设计稿一样多，甚至更多。
   - **又平又碎，就是用户一直说的“杂、碎”的直接原因。**
2. **绿色一侧的颜色跑偏了。** 设计稿的草是柔和的橄榄绿，冷暖有变化。现在是一整片柠檬黄绿，高草丛是亮翠绿，饱和度比设计稿高 40%–70%（0.60–0.65 对 0.39–0.44）。
   - 但只把饱和度降下来会发灰发脏（见 `10_desat_test.jpg`）。设计稿“鲜而不刺眼”靠的是冷暖明暗，不是低饱和，所以颜色要和光一起改。
3. **东西摆得太满、太匀。** 设计稿一屏只有一个主角（一个营地、一座塔或一个口子），周围大片安静的地面。
   - 现在同样的画幅里有 4–6 段同样长、同样做法的墙，石头总是成对堆在墙头，草丛块块一样大（见 `01`、`04`、`13`）。
   - 这一条一半是画面问题，一半是布局问题（每方 26 段墙是 2.1 灰盒按玩法定的），要动先问用户。

**不是主要原因的：three.js 本身和模型面数。** Dota 2 自己就是实时光照加手绘贴图。我们的建筑也不算低面数，我方水晶的文件有 1.8MB。差的是光照场景太简单、物件没有自己的明暗，不是引擎做不到。

**最该先做的三件**（不重出素材、不动玩法，几天内能看到效果）：
- ① 重配光：天光补光减半，阴影加浓并偏冷，太阳偏暖。
- ② 全图铺一层“画面外的树冠投影”：大块、柔和的影子，按世界坐标乘到地面、墙、草上，慢慢飘。
- ③ 草丛接受阴影、根部压暗；调色饱和度回到 1.0 左右，草地从柠檬黄绿往橄榄绿拉。

估计这三件能把绿色一侧“亮、平、刺眼”的观感差距缩掉三到四成。剩下的差在两处：一是物件本身（墙和建筑没有自己的风化明暗，塔和水晶的造型不对），二是构图太满。这两处要做中档和大动的工作。

示意图见第五节：用即梦图生图画的，只改光、颜色、地面，**不是实现结果**。

- 河床：现在是一模一样的扁圆石平铺，图案感很强；设计稿的石头大小不一、有明有暗。
- 岸：现在是一条直线；设计稿是一段段砌石和湿的暗带。

**04 基地口子**
- 构图：设计稿一个口子、一座塔、一段弧墙。现在同一画幅里有三座高地塔、三段台阶、四段弧墙、四块草丛，这是布局决定的。
- 墙：设计稿城墙高、墙脚暗、爬藤、顶上长草；现在矮而方，墙面是一样的砖纹加绿斑。
- 台阶：设计稿坡道窄、两边有护墙，和铺石连成一体；现在是一大块平整的楼梯，和地面的接缝很硬。

**05 我方中路外塔一带**（设计稿是用户点名喜欢的那座塔）
- 塔：设计稿是“石芯 + 青铜肋片 + 爪托晶体”，底下多层台基；现在是细长的花瓶形，缠着绿色大理石飘带。塔脚的同心圆铺地两边都有，这一处做到了。
- 石板路：现在被调成黄绿，和草几乎一个颜色，路形看不清。
- 光：设计稿左侧有大片树影；现在没有。

**06 对方中路外塔一带**：最接近设计稿的一组。
- 差在：墙发蓝；草丛发亮发橙、太多；塔顶是一块平涂的橙色多面体，设计稿是铁笼里一团火；整体光不够沉。
- 说明一件事：同样的光照和管线，红色一侧好得多，因为暖色不怕饱和；绿色一侧一饱和就成了柠檬色。

**07 我方外塔近景**：造型差距最大的一组。
- 设计稿是粗壮的钟形塔身、三层台阶台基、青铜包边、弯角托尖晶；现在细、瘦，台基只是一圈石环。
- 材质：现在塔身是平铺的石纹加大块绿色大理石；设计稿有砌缝、包浆、边缘磨亮。

**08 我方水晶**
- 造型：设计稿是往上张开的金边白石托座，晶体从里面长出来，地面有金色嵌线；现在是合拢的暗绿色“触手笼子”。
- 颜色：饱和度 0.26 对设计稿 0.16，暗绿金属吃掉了画面。
- 边上：一棵粉树渲染成了紫色的球；城墙外是一片糊的绿。

**09 我方出生点**
- 尺度：设计稿是抬高的大平台，背后带月牙的拱门、两座雕像，水顺台阶流进水槽通到水晶；现在是墙角里一个挤着的小水池。
- 墙外：画面左边将近一半是**模糊的绿色空地**（城墙外面用的是低清总览贴图，再往背景色里淡出）。这是玩家复活时一定会看到的位置。

## 三、分层归因

**1. 光和气氛：大部分是“没有”**

| 设计稿里有的 | 现在 | 判断 |
|---|---|---|
| 画面外树冠投下的大片影子 | 树只种在城墙外，影子只够到地图边上一圈 | 没有 |
| 暖光对冷影 | 天光补光 1.4 太强，阴影被冲淡成灰 | 有，但量太小 |
| 接地的暗部 | 一圈程序画的模糊黑线，没有方向和渐变 | 有，但做法到不了 |
| 凹处、接缝更暗（环境光遮蔽） | 没有 | 没有 |
| 空气感 | 没有雾，只有一圈暗角 | 没有 |
| 高草丛内部暗 | 草丛不接受阴影，叶子法线一律朝上，草永远是亮的 | 做法到不了 |

**2. 地面：有，但做法到不了**
- 笔触和细节都有，重绘质量够。
- 大块的颜色组织没有。原因是两步有意的处理：重绘提示词要求无投影、明暗很缓；拼接时把低频颜色拉回平涂的布局图。这两步当时是对的：不然影子会画死在地上、和实时影子打架，九个区也接不上。结果就是地面的大尺度只剩平涂。
- 设计稿的大块明暗，一半来自光，一半来自地面自己的深浅（踩秃的路、湿洼地、草的疏密）。后一半我们也没有。
- 路和草的过渡做得不差，但我方石板路被调成黄绿后路形不清。

**3. 植被：树冠“没有”，草“做法到不了”**
- 树：地图里面没有能投影的树（2.1 定过树只放够不着的地方）。城墙外的树是二十面体捏的叶团，近看是一个个球。
- 高草丛：形态是对的。到不了的是颜色和明暗：叶尖是亮黄绿 `(0.62, 0.70, 0.36)`，整丛比地面亮，又不接受阴影；设计稿的草丛比地面暗一档。
- 设计稿是草贴着墙根长成一整圈；现在是墙一段、草一块，分开摆。

**4. 石头、墙、建筑：有，但做法到不了**
- “平铺贴图”这个猜测对：墙、石头、塔、水晶、出生点全用同一张按世界坐标投影的石纹（约 3.3 米重复一次）。Codex 建的模型只带形状，材质进游戏时被统一换掉。青苔是朝上面上的噪声，所以是均匀的绿斑。缝里没有脏，边缘没有磨亮。
- “低面数”这个猜测不对。
- “硬边”对一半：墙的倒角小、像积木，建筑还行。
- 塔和水晶的造型偏离设计稿，这是建模那一步的问题。
- 对方石头本色带紫。

**5. 构图和密度**
- 墙的位置有玩法逻辑（草丛背后、营地凹口、路口），但每方 26 段墙是同一个配方，视觉上没有主次。
- 三条线的高地塔挨得近，所以一个口子的画面里有三座塔。
- 城墙外是糊的绿；设计稿那里是远景（树、山、云）。

**6. 颜色**
- 绿色一侧饱和度高，来源有三处：拼接时我方一侧整体乘了偏黄绿的色调；草丛叶尖的亮黄绿；调色的饱和度 ×1.14。
- 绿色基本只有一个色相；设计稿阴影里偏青绿、阳光下偏黄绿。
- 红色一侧多出一个不该有的蓝色：色相离散度 57°，设计稿是 26°。
- 基地里：设计稿是白石、金、青三色；现在是灰石加大面积的暗绿金属。

**7. 技术根因（逐条核对猜测）**

| 猜测 | 结论 |
|---|---|
| 设计稿光影是画死的，实现是实时光照 | 对，但不是做不到的理由。Dota 2 就是实时光照，也有大块明暗。我们缺的是遮光物（树冠、云影）、环境光遮蔽和冷暖对比 |
| 贴图里没有光影信息 | 对，而且是故意的（提示词明写）。所以缺的大块明暗应该由引擎补，这部分没做 |
| 分区重绘丢了全局明暗 | 对一半。不是“丢”，是拼接时有意拉回平涂 |
| 程序摆放没有构图 | 对一半。有玩法逻辑，没有视觉主次 |
| 硬边、低面数、平铺贴图 | 平铺贴图对；硬边对一半；低面数不对 |

清单里没有、这次核实到的根因：
- 天光 1.4 对太阳 3.0，补光太强；阴影浓度 0.84、边很软，影子又浅又糊。
- 草丛不接受阴影。
- 调色的饱和度 ×1.14。
- 城墙外是低清贴图。
- 对方石头本色带紫。

## 五、示意图（即梦图生图，是示意，不是实现结果）

`14_target_jungle_me.jpg` 和 `14_target_tower_me.jpg` 是三联图：现在 / 示意 / 设计稿。单张在 `target_jungle_me.jpg`、`target_tower_me.jpg`，底图是 `ref_now_*.jpg`。提示词要求物件位置、大小、数量都不变，只改光、颜色、地面。

看图得出的几点：
- 只换光和颜色，物件就和地面融到一起了，石头有体积，草有冷暖。这印证了“光是第一大差距”。
- 但示意图比设计稿暗、更沉，影子是碎的树叶斑。设计稿是亮而通透的大块影子。所以第 1 项要做大块、柔和的影子，整体亮度不能压太低，否则会换成另一种“碎”。
- 示意图里一屏还是五段墙，和设计稿的“干净”仍差一截。构图（第 8 项）是光改完以后剩下最大的差距。

## 六、没能核实的

**核实时看的代码**：
