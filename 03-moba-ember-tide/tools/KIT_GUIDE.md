# 写一个英雄的技能和特效

给并行干活的 agent 用，也是以后加英雄的手册。每个英雄一个 agent，各在自己的 git worktree（自己的分支）里干，只改自己英雄的那一个文件。

## 要做的事

实现 `src/map/game/heroes/<id>.ts`。文件开头的注释是这个英雄的规格（每个技能怎么放、数值多少），下面是空壳：属性、颜色常量、
每个技能的名字和说明已经写好，`fire() { /* 待实现 */ }` 要你写。做完以后在测试场里这个英雄的普攻和每个技能都能放、效果和数值与规格一致、
每个技能都有像样的特效。

## 先读（按顺序）

1. `src/map/game/heroes/lan.ts`：做完的样板。一个被动、一个非指向（带位移）、一个直接放的增益、一个自己接管流程的大招。
2. `src/map/game/skills.ts`：技能怎么定义（`SkillDef`、`Cast`、`HeroKit`），以及技能里能用的全部现成动作（`Api`）：
   伤害治疗护盾、眩晕定身沉默减速嘲讽易伤、推开拉拽、增益、找目标（圆、直线、扇形）、弹道（直线、追踪、抛物线）、持续范围、定时、冲刺闪现。
3. `src/map/game/fxlib.ts`：特效零件。开头的注释是规矩，必须遵守。
4. `src/map/game/actor.ts` 开头的注释和 `Actor` 接口：英雄的状态、`a.hand()`、`a.chest()`、`a.pos`、`a.lock()`、`a.anim()`、`a.data`（技能跨帧存东西）。
5. `tools/kit_test.mjs` 开头的注释：怎么测。

## 环境

你在一个 worktree 里，和主目录 `/Users/jadon7/Documents/SynologyDrive/code/moba`（下面叫 MAIN）是同一个仓库的不同检出。开工前：

1. `ln -s MAIN/node_modules node_modules`（依赖不用重装）。
2. 起自己的开发服务器（后台跑，端口用分给你的那个）：`MOBA_PUBLIC=MAIN/public npx vite --host --port <端口> --strictPort`。
   `MOBA_PUBLIC` 让它用主目录里最新的模型和贴图。主目录的服务器在 5183，不要动它。
3. 测试：`MOBA_URL=http://localhost:<端口>/map.html node tools/kit_test.mjs <id> <输出目录> [只测哪几个键]`。
   它在测试场里把普攻和每个技能各放一遍，打印靶子的掉血、状态、位移，并给每个技能出一张连拍图 `<输出目录>/<键>.jpg`，用 Read 看。
   输出目录放在你的 worktree 外面的临时目录，或者 worktree 里的 `.tmp/`（不要提交）。
   截出白屏、或者它报 `blank`，是显卡正被别的任务占着：等半分钟重跑；连续三次都这样就在报告里说。
4. 想看得更近、换角度或者试别的目标，用 `tools/play_test.mjs`（步骤脚本，见它开头的注释），网址参数 `arena=1&h=<id>`；
   页面上有 `__arena`、`__play`、`__sim`、`__api`、`__fx` 可以直接调。

## 规矩

- **只改 `src/map/game/heroes/<id>.ts`。** 框架（`skills.ts`、`fxlib.ts`、`actor.ts`、`sim.ts`）和别的英雄的文件不要动：五个人同时在改，
  动共用文件会互相冲突。框架里缺的东西（比如少一种粒子图形、少一个查询），在自己的文件里直接用 three.js 补一个；
  确实是框架的 bug、绕不过去的，停下来在报告里写清楚现象和你认为的原因。
- 数值照规格。觉得不合理（太强、太弱、和动作对不上）就在报告里说，不要自己改数。
- 英雄的模型在 `MAIN/public/assets/hero/<id>.glb`，现在可能只有一个站姿（动作还在做）。没有技能动作时英雄会站着把技能放出来，
  这不影响你：特效的位置用 `a.hand()`、`a.chest()`、`a.pos`、目标的位置，不要依赖某一帧动作。出手时机以后由主线按动作时间表对。
- 不要调用即梦、Tripo、Codex。不要打印密钥。结束进程只用确切的 PID（先 `lsof -nP -iTCP:<端口> -sTCP:LISTEN` 查到再 `kill <PID>`），
  禁止 `pkill`、`killall`。`rm` 只写完整的绝对路径。
- 可以在自己的分支上提交，而且只提交 `src/map/game/heroes/<id>.ts` 这一个文件。不要切分支、不要合并、不要推送。

## 特效要做到什么程度

用户的原话：“英雄需要有一个大招，普通技能也要有一些特效，不能仅仅是模型动作”；标杆是 Dota 2。他同时反感“光污染”和“杂、碎”。所以：

- 每个技能三层：**出手**（手上或武器上的一点预兆，零点几秒）、**过程**（飞行的弹体，或者铺开的范围）、**命中或落地**（闪一下、溅开、地上留痕）。
- **看得懂**：范围技能的边界要清楚（玩家得看得出打到哪）；持续的区域在持续期间一直看得出还在，快结束时淡出；
  弹道有头有尾，飞行方向一眼看得出；延迟生效的技能（蜡封、烛火柱、漩涡的最后一响）在生效前要有清楚的预告。
- **克制**：最亮的那一下不超过四分之一秒；叠加发光（`add: true`）只用在火花、火心、闪光上，烟、尘、水、蜡用普通半透明；
  不加常亮的光源；颜色只用文件里那几个常量的色系，不要彩虹。
- **融进场景**：地上留的东西（焦痕、水渍、蜡、裂纹）用 `decal`，颜色往地面的色系靠，淡出要慢；
  水系的英雄多用水珠、水柱、水面；火系的多用余烬、烟、焦痕，火焰本身要小而亮。
- **有分量**：重的技能（砸地、撞击、大招的最后一下）加一点镜头抖（`fx.shake`，0.05 到 0.15）和一圈冲击波；轻的技能不要抖。
- 大招要明显比小技能隆重：范围更大、层次更多、持续更久，但仍然守上面的克制。
- 性能：一个技能同时活着的粒子几百个以内；不要每帧新建材质或几何体；`kit_test` 最后打印的 fps 低于 50 要查原因。

## 做完的标准

1. `npx tsc --noEmit` 没有报错。
2. `kit_test` 的报告：普攻和每个技能都“放出去了”，掉血、状态、位移和规格对得上（测试场里英雄是 15 级；对面小兵没有护甲魔抗，对面的假人英雄有）。
3. 每个技能的连拍图你自己看过，至少改过两轮：第一轮做到能用，第二轮对着图挑毛病（太亮、太碎、范围看不清、浮在地面上不融合、太快看不见或者拖太久）。
4. 提交到自己的分支，停掉自己的开发服务器。

## 报告

给主线一段话：
- 每个技能实现了什么、和规格有没有出入。
- `kit_test` 报告里的关键数字（每个技能打了多少、上了什么状态）。
- 你自己看连拍图挑出来、但没解决的问题。如实写，不要只报喜。
- 觉得规格里不合理的数值；希望框架加的东西；遇到的框架 bug。
- 分支名和提交号。
