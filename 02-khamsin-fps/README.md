# KHAMSIN · 热风行动

一款网页 FPS：原创中东沙漠城镇地图「卡姆辛旧城」（三路两点结构）+ 飞行员跑酷（滑铲 / 二段跳 / 蹬墙跑 / 钩爪 / 滑索）+ 机甲空降与驾驶。

- 场景和追猎者机器人的**模型由代码程序化生成**（机甲、枪械、士兵是 Blender 脚本建的模型，见下），光照在载入时烘焙（逐顶点 GI），音效与配乐实时合成。
- 人类士兵（友军、敌军、狙击手）是**真人模型**（`assets/models/soldier.glb`，实验分支 `experiment/human-characters`）：人体来自 Blender 基金会 CC0 的 Human Base Meshes，作战服、装备、头盔 / 头巾 / 兜帽由 `tools/blender/build_soldier.py` 在它外面生成，并绑定到游戏原有的骨架上，所以动作仍是程序化动画。远处的兵用简化的替身投影。取不到模型时退回原来的程序化士兵；URL 加 `?nosoldier` 可强制使用程序化士兵做对比。
- **步态是程序化的**（`src/game/gait.js`）：骨架 14 个关节（比原来多了左右脚踝），相位按实际走过的距离推进，全掌踩实的那只脚锁在地面上不打滑；腿用两段反解，脚掌按“脚跟着地 → 全掌 → 抬脚跟蹬地”滚动；骨盆高度由两条腿够不够得着落脚点来约束，走路时的上下起伏是自然带出来的。侧移时迈横步，后退是把向前走的周期倒着放；台阶和坡道上两只脚各踩各的高度；不动时是持枪的戒备站姿，蹲下是跪姿射击。上半身反向抵消骨盆的转动，枪口保持稳定。检查工具：`tools/gait_probe.js`。
- 三把枪与第一人称手臂是用 **Blender 无界面脚本**建的硬表面模型（放样截面、布尔切口、倒角 + 加权法线），导出为 `assets/models/*.glb`；取不到 GLB 时退回程序化枪模。
- **机甲「砂暴」K-07** 也是 Blender 无界面脚本建的硬表面模型（`tools/blender/build_mech.py` → `assets/models/mech.glb`，机体约 4.6 万三角形 + 座舱内饰约 0.8 万，共 1.75 MB）：三管机炮、动力拳、八联装火箭巢（发射时开盖）、可上翻的座舱盖、会转动的传感器头；敌我两套涂装共用一个模型，由 `src/game/mechloader.js` 按部件名装到关节上。取不到 GLB 时退回原来的程序化方块机甲，URL 加 `?nomech` 可强制退回。重新生成：`Blender -b --factory-startup -P tools/blender/build_mech.py -- --preview`。
- 机甲步行（`src/game/mechgait.js`）：步态时钟按实际走过的距离推进，两脚严格差半拍；落地的脚钉在世界坐标上（支撑脚水平滑移为 0），腿用两段 IK 去够，骨盆高度受腿长约束；冲刺时双脚离地由推进器带着走。
- 驾驶座舱（`src/ui/cockpit.js`）：挂在相机上的立体内饰 + 全息 HUD。仪表台是三联屏：中央主屏（机体示意图、完整度、速度 / 航向 / 反应堆 / 步行机构）和两块向驾驶员内收的翼屏（左雷达、右武器：炮弹、炮温、八个火箭筒、动力拳、熔毁核心），屏幕带边框按键；上方是八格告警灯条（装填 / 火箭 / 过热 / 护盾 / 冲刺 / 受损 / 锁定 / 弹射）和主警告、主注意灯；还有旋钮、拨杆、带红色护盖的总保险、遮光檐、备用罗盘、加粗的风挡立柱、顶部的拨杆与断路器、弹射拉环，以及随移动 / 转向摆动的两根操纵杆。屏幕、告警条和面板刻字都是画布贴图，按 `build_mech.py` 里同一组常数摆放。全息 HUD 仍显示准星、弹药、火箭 / 动力拳冷却、核心、机体与护盾、罗盘带、锁定与来袭告警；登机有约 1.2 秒的启动序列。
- **第一人称能看见自己的武器**：驾驶时两臂向内、向上、向前收拢（`mech.js` 的 `FP_R` / `FP_L`），转管机炮从右下伸进视野、动力拳在左下；开炮能看到炮口焰、炮管旋转和后坐，出拳时前臂横贯左半个画面；转向时武器略微滞后。别人看到的机甲姿态不变。开发用检查台：`tools/mech_probe.js`（清场、摆机位、测支撑脚打滑）；只重渲座舱预览：`build_mech.py -- --ckpreview`。
- 第一人称的手与前臂（`tools/blender/khhand.py`）：按手骨比例生成手掌和五指，手指逐节弯曲到贴住握把，再把所有体块体素熔合成一整只手套（指根、虎口没有接缝）；护垫、缝线贴着手套表面生成；袖子的褶皱来自 Blender 布料解算；左前臂钩索发射器上的小屏实时显示钩索充能。
  - 细节：铣削凹面、内六角螺丝、滚花旋钮、带凹槽的枪管、镂空护木、折叠机瞄、可折叠枪托等；逐顶点烘焙了遮蔽、棱边凸度和缝隙凹度。
  - 材质：带清漆层的物理材质（深色阳极氧化枪身、裸钢件、沙色涂层金属），棱边磨损露出亮钢，缝隙里积沙尘。
  - 反光随环境变化：每几帧从视点朝太阳打一条射线，太阳照到时环境反射强、清漆高光锐利；进了阴影明显变暗变哑。
  - 全息准星是细环 + 小中心点；开镜时自动关掉护木上的弹药屏。机身上有序列号、保险标记、激光警示牌等小标识。
  - 枪械用单独的投影绘制：近裁面极近（开镜时机匣后部不会被裁开），深度压在最前面（贴墙时不会插进墙里）。
- 地表与墙面使用 [Poly Haven](https://polyhaven.com) 的 **CC0 实拍 PBR 贴图**，天空与日光来自一张实拍 HDRI（太阳方向、直射/天光比、雾色都从它分析得出）。清单见 `assets/CREDITS.md`。
- 找不到 `assets/` 时会自动退回纯程序化贴图与天空，仍可运行。

## 地图：卡姆辛旧城（三路两点）

原创布局，按经典爆破图的思路组织：两端出生区、三条各有性格的路线、两个各有 3–4 个入口的据点，路口都收成门洞、坡道或台阶。

- **东路 · 长街**：一百多米的长直线，南口是只剩门墩的断拱门，中段是塌陷的弹坑（下沉 1.6 m，可当掩体），尽头向西上坡到 A 点。全程机甲可通行。
- **中路 · 广场**：南大道 → 喷泉广场 → 中门（半开的双开木门，只容人过）→ 巴扎十字 → 北大道。东西两条巷子通向另外两路，巷口各有一道拱门墙。
- **西路 · 运河**：下沉 3.4 m 的干河床，穿过水门的大拱进入涵洞（河道加盖的 28 m 暗段，顶上有透光格栅），沿涵洞台阶上到 B 点西拱门。上层的运河路被水门截成两段。
- **A 点 · 货栈高台**（东北）：高 2.6 m 的石台，四条路上去——长街的东坡道、巴扎的短阶、北大道的西阶、敌方出生区的北阶。台上有可进入的货栈和残存的柱廊。
- **B 点 · 泵站院**（西北）：四面围墙——西拱门（涵洞来路）、东侧 B 门（双开木门）、北缺口，南墙只有一个窗洞（铁驭可以翻，步兵过不去）。
- **暗道**：西南街区的底层打通成室内通道，连着市集街、运河路、西巷和工坊。
- 导航网格、小地图、AI 的交战点都从关卡数据自动生成（`src/world/level.js` 的 `combatPoints`、`zones`）。

## 第二张地图：双界回廊（相位试炼）

主菜单点「双界试炼（相位切换）」，或在网址后加 `?map=rift`。同一条路线存在于两重空间里：**现世**（白昼）与**蜃界**（同一个太阳下的冷色幽暗世界）。两界的地形和主体建筑一样，差别在「哪里有路」。

- **T · 相位切换**：位置、速度、朝向都保留，只换世界（0.45 秒冷却）。目的地有实体就切不过去（会先试着挪开半米以内）。
- **按住 Z · 蜃影透视**：把另一界与这一界不同的结构描成全息网格，另一界的敌人显示成剪影（隔墙可见）。
- **巧用**：
  - *空中切换*：断桥的南半截只在蜃界、北半截只在现世；蹬墙回廊的墙左（现世）→ 右（蜃界）→ 左（现世）交替；升井的平台一层一界。动量保留，所以是「起跳 → 切换 → 接上」。
  - *因果联动*：出口的闸门在现世关死，机关在蜃界的回廊上——在一界拉下，另一界的门打开。
  - *相位闪避*：每个单位只和同一界的东西发生关系（碰撞、视线、子弹、爆炸）。切走之后追你的敌人会丢失目标，去你消失的地方搜；扔出的手雷留在原来那一界。
  - *相位处决*：切换到敌人所在的位置上，直接处决。
- **示范演示（录制用）**：这张图的主菜单里点「示范演示（录制）」，或网址加 `?map=rift&demo`。第一人称自动跑完全程（约 45–55 秒）：沿途透视、断桥和蹬墙段的空中切换、拉机关、隔界猎杀（在蜃界盯着现世守卫的剪影走到他身上，切过去处决，再切回来找下一个）。只通过虚拟输入操纵玩家本体，不改物理、不无敌（`src/game/riftdemo.js`）；`H` 隐藏界面，`Enter` / 点击接管，`Esc` 返回，跑完 8 秒后自动再来。
- 守卫：现世是步兵（断桥对岸 1、大厅 3、天台 2），蜃界只有大厅里的一个追猎者，蜃界的天台不设防；守卫只管自己驻地周围 24 m，丢失目标后会去目标消失的位置查看。
- 路线：起点院（大门）→ 甬道（塌墙）→ 断桥 → 蹬墙回廊 → 守卫大厅（机关 / 闸门）→ 升井 → 天台信标。六个检查点，坠入深沟或阵亡回到最近的检查点；计时、奖牌（金 70 秒 / 银 110 秒）和最佳成绩存在浏览器本地。
- 实现：两界各建一遍（`src/world/rift.js` 的 `buildRift(B, K, ph)`），各有自己的碰撞 BVH、光照烘焙和导航网格；游戏里共用一个 `World` / `Nav` 上下文对象，`Game.setCtx(k)` 在更新每个单位之前把它切到那个单位所在的界（`physics.js` / `nav.js` 的 `use()`）。切换画面 = 换静态场景组 + `Engine.setAtmos()` 换一套太阳 / 天光 / 雾 / 调色 + 后处理里的冲击波（`uShift`）。模式逻辑在 `src/game/riftmode.js`，界面在 `src/ui/rifthud.js`。

## 第三张地图：风歇驿堡（导入的灰盒地形）

主菜单点「地图 · 风歇驿堡」，或在网址后加 `?map=yard`。玩法和旧城一样是消耗战：一座由多进院落、回廊、拱廊厅堂和塔楼组成的沙漠驿站堡垒，我方从南面的院子出发，敌方在北面空降。

- **地形是导入的**：`tools/vmf2map.py` 把一份 Hammer 灰盒（`.vmf`）转成 `assets/maps/yard.kmap`——5885 个笔刷的 3.3 万个面、613 块位移地形、隐形墙和灯位，压缩后约 0.57 MB，进这张图时才下载。灰盒只有体块，没有任何材质和陈设。
- **材质和画面是本作自己的**（`src/world/yard.js`）：
  - 每个面按朝向、尺寸、离地高度、头顶有没有楼板分派材质：灰泥墙（剥落处露砖）、砂岩、石板铺地、抹灰屋面、木梁门窗框、铁栏杆、沙土地形、岩石。
  - 墙脚返潮发暗、墙头雨痕，每段墙破损程度不同，墙面颜色按街区成片变化；露天铺地成片积沙，室内只有零星一点。
  - 灰盒里被标成「不渲染」的面（屋顶、墙背后，原作者假定玩家到不了）只要露在外面就补画出来——铁驭会蹬墙上房，机甲视点也高。
  - 陈设由导航网格自动摆放，只占宽敞处的墙根，不挡路：货箱、油桶、陶罐、麻袋、沙堆、沙袋掩体、棕榈、草丛、遮阳棚、横拉的彩旗、屋顶的水箱和天线。
  - 灰盒里的 29 个灯位换成灯笼并烘进光照，室内按间距再补；不见天的区域登记成浮尘体，阳光从门洞射进来是光柱。
- **玩法数据是算出来的**：两队空降点、重生点、交战点、机甲投放点、狙击位、菜单和开场镜头都由导航网格生成，没有手写坐标。
- **没有空气墙**：灰盒原本靠 328 块隐形墙把人圈在里面——每个院子上方 7–8 m 处都盖着一层看不见的「盖子」，四周还有挡板。本作的铁驭会二段跳、蹬墙、钩爪，到处撞上看不见的东西。现在：
  - 隐形墙只留 16 块楼梯上的平滑坡（只留斜面本身，贴着台阶，不挡人），其余 312 块全部去掉，屋顶和塔楼随便上。
  - 通往堡外的三处出口（西侧券洞口、西南巷口、东北断墙处）砌成关着的城门：砂岩门墩和过梁、带铁箍和门钉的双扇木门、门闩，门上方砌墙压顶。原来被隐形墙隔在外面、其实在堡内的东南下沉院和东侧小院直接开放。
  - 「画面上没有、却撞得到」的面也清掉了：被标成不渲染的面按 0.5 m 的间距取样判断是否露出，窗洞上沿、挑檐底面这种只露一小条的也会画出来；立着的岩壁两面都画。
  - 翻出堡外或掉到地图底下：屏幕提示「已离开战区」，4 秒后送回最近的重生点，不算阵亡（`game.js` 的 `checkOOB`，范围是 `yard.js` 的 `YARD_OOB`）。
  - 检查工具 `tools/airwall_probe.js`：从可走区域上方撒射线，统计「碰撞体挡住了、但 0.3 m 内没有任何可见表面」的次数。改之前 5893 条里有 2805 条（48%，几乎全是院子上空那层盖子），现在 39273 条里 2 条（两处陈设的碰撞盒比外形大 0.3–0.4 m）。
- **导航为它做了几处通用扩展**（`src/game/nav.js`，旧地图不受影响）：格子可以设成 0.5 m（灰盒的门洞只有 1.2 m 宽）、可设四周净距和相邻格高差、每格可看更多层表面、可接「某点是否在实心体内」的精确判断（上下紧贴着叠放的实体，光靠射线判断不准）。
- **数字**：约 29 万三角面；连通的可走区域约 5200 m²，其中机甲能走约 1200 m²；首次进入要烘焙光照（桌面约 30 秒，之后有缓存）。
- **已知的取舍**：城门挡的是地面上的路，铁驭从屋顶仍然翻得出去，靠「离开战区」送回；AI 只在最低一层活动，不上二楼和屋顶。
- **重新转换**：`python3 -I tools/vmf2map.py <地图.vmf> assets/maps/yard.kmap --center=-8,0,-24`（`--preview 图.png` 出俯视图，`--stat` 看统计）。换一份灰盒的话，`--center` 要按它的范围重新定，让可玩区域落在原点附近、两队沿南北向分布。

## 第六张地图：布局图地图（从一张俯视布局图自动生成）

主菜单「选择地图 · 布局图地图 · 灰盒」，或网址加 `?map=layout`（`&src=文件名` 换一张布局图）。

盐井镇之后的反馈是「怎么还是四四方方的」：问题出在可走区域的形状上。经典攻防图的俯视图里，能走的地方是一条条走廊和一个个房间连成的网，中间夹着大块走不进去的实心区，外轮廓凹凸不齐；盐井镇是先铺满一整块矩形再往里摆房子，从上往下看永远是个方块。这一版改成「先画平面图，再按图搭」：

- **布局图的规范**（`tools/layout_prompt.md`，也是给 AI 生图用的提示词）：白 = 实心 / 走不进去；石板蓝 = 地面；橄榄绿 = 高台（+3.2 m）；深蓝 = 下沉区（−3.2 m）；黄 = 楼梯 / 坡道；浅灰小块 = 掩体；橙色细框 = A 点；品红细框 = B 点；亮绿 / 红 = 进攻方 / 防守方出生区；不要文字、渐变、阴影。
- **转换**：`python3 tools/layout2map.py 布局图.png 输出.json --size 134`（`--preview 预览.png` 出一张识别结果）。按颜色分类，每 0.5 m 一格记地面高度和标记；实心区域用 OpenCV 提成多边形（斜墙就是斜的）；掩体、楼梯提成旋转矩形；外围只留贴着可走区域的一圈外墙，再往外是沙地。
- **搭建**（`src/world/layoutmap.js`）：地面按格子合并成块；实心多边形挤出成墙体，沿边 7.5 m，往里缩进 1 m 后按 ~12 m 一栋随机加高 0–6 m（屋顶高低错落）；朝街的墙面开门窗；两边都是墙的下沉通道自动封顶成隧道；楼梯按两头的地面高度定方向，太陡的自动加长到不超过 32°；每个出生区出口往里 4 m 立一道影壁；站到墙体顶上算离开战区。

## 光照是怎么做的

对照《使命召唤：现代战争 II》沙漠地图的实机截图与动视公开的渲染资料（预计算光照 + 探针、GTAO、高光遮蔽、反射探针归一化）调的：

- **低角度日照**：实拍 HDRI 的太阳约 38°，再把整张天空朝太阳一侧压低 9°，得到约 29° 的太阳 —— 大面积阴影里夹着小块强光，影子很长。
- **间接光遮蔽只压间接光**：屏幕空间 AO（4×4 交错采样 + 4×4 双边滤波）存成贴图，下一帧在材质里按世界坐标重投影采样，只衰减天光 / 反弹光 / 环境反射，直射阳光保持干净；带 GTAO 的多次反弹近似与高光遮蔽。
- **逐顶点烘焙 GI**：太阳一次反弹 + 天光可见度；天空反射按可见度衰减并补上周围表面的平均反弹光（近似探针归一化），室内不会泛天光。
- **反照率校准**：每张实拍贴图按实测平均色乘一个增益，落到目标反照率（沙 0.42/0.36/0.27、石铺地 0.33/0.30/0.26 …），整体是低饱和的灰米色。
- **视差遮蔽映射**：铺地与砂岩用高度图做 POM，石缝有真实的凹凸与遮挡。
- **体积光与尘雾**：四分之一分辨率下沿视线步进 32 步（再按深度上采样，2560×1440 下约 0.3 毫秒），逐点查询太阳的级联阴影，得到任意角度可见的光柱和阴影体积；密度是贴地的指数高度分布乘上随风平移的 3D 噪声（流动的尘雾），散射色乘了沙尘的反照率。浮尘粒子用同一张阴影图，只在阳光里发亮。
- **丁达尔光柱与浮尘**：涵洞、暗道、货栈、茶馆、巴扎顶棚下这些不通风的地方登记为「室内浮尘体」（`level.dustVolumes`），体积光在里面按更高的浮尘浓度、更接近各向同性的相函数计算——阳光从高窗、门洞、格栅、板条缝射进来就是一道道光柱。镜头附近另有一层细密的浮尘粒子，只在被太阳照到的地方发亮，进了室内才明显。
- **明暗适应**：曝光跟随画面亮度，明适应快（约半秒）、暗适应慢（一两秒）。从亮处走进暗室，先是一片昏暗、颜色发灰，再慢慢看清；从暗处出来，头一瞬间泛光加重、发白，随后收住。镜头在室内时补偿幅度更大（靠导航网格里记录的天空可见度判断）。
- **氛围细节**：城外四根被风吹斜的战场烟柱、场内三处闷烧轮胎堆的黑烟、远景的热浪抖动、强光附近的镜头脏污。
- **大气**：指数高度雾 + 朝阳方向的散射染色；AgX 色调映射 + 轻微分离色调。

## 怎么玩

- **推荐**：双击 `启动游戏.command`（或 `dist/启动游戏.command`），会开一个本地服务器并自动用默认浏览器打开。
- `dist/` 是可以单独拷走的发行版（`index.html` + `assets/` + 启动脚本）。首次打开只下载约 12.6 MB 的压缩版素材；文件夹里另有约 59 MB 给旧浏览器用的后备原文件，`node tools/build.mjs --lean` 可以不带它们。
- 直接双击 `dist/index.html` 也能玩，但浏览器不允许本地文件页面读取贴图，画面会退回程序化材质。
- 首次进入要烘焙全局光照（十几秒），之后会缓存，再进只需几秒。
- **自动对战（录制用）**：主菜单点「自动对战（录制）」，或在网址后加 `?demo`。AI 以第一人称接管玩家，连贯使用滑铲、蹬墙、二段跳、钩索、换枪、手雷和近战；不需要锁定鼠标。`H` 隐藏界面，`Enter` 或点击画面接管成手动，`Esc` 回主菜单；一局结束 8 秒后自动再开。
- 双方各有 2–3 名 **AI 铁驭**（`src/game/aipilot.js`），和玩家用同一套本体物理与同一个大脑（`src/game/brain.js`）；步兵在转移和受击时会滑铲 / 侧滑。目标分因此上调到 150。
  - 自动对战时敌方多投 3 个步兵、开局就是 3 名铁驭，比分不至于一边倒；每局只开一次机甲（约 35–55 秒），其余时间徒步作战；一局约 4–5 分钟，结束后自动再开。
  - 大脑不依赖任何写死的坐标：靠射线找可蹬的墙、可钩的屋檐、可翻的矮墙；站在屋顶 / 顶棚上被挡住时会找落差跳下去；追击站在墙头或屋顶上的敌人时，改为去一个看得见对方的落脚点。
- 请用独立的 Chrome / Edge / Safari 窗口游玩。内嵌预览面板不支持鼠标锁定，只能用「兼容模式」（鼠标移到屏幕边缘转向），手感差很多。

## 手机 / 平板与 PWA

手机、平板上直接打开网址就能玩，不用装任何东西；也可以装到主屏幕当应用用。

- **始终横屏**：竖着拿手机时，整个画面（3D 画布 + 界面 + 按钮）会旋转 90° 按横屏显示，把手机逆时针转过来（顶部朝左）就是正的；系统没锁方向时把手机横过来，浏览器自己转屏，画面随之恢复正向。安卓上点「开始」会进入全屏并把方向锁成横屏；iPhone 的浏览器不提供这两个接口，由上面的整体旋转兜底。
- **触屏操控**：左半屏按住拖动是浮动摇杆（向前推自动冲刺），右半屏拖动转视角，按着任何一个按钮拖动也能转（边开火边跟枪、边跳边转向）。右下一圈是开火 / 跳 / 蹲滑 / 瞄准（点一下开镜，再点收镜）/ 换弹 / 切枪 / 手雷 / 近战 / 钩爪；小地图下面是呼叫机甲（双界试炼里换成「透视」）；靠近机甲、滑索、机关时屏幕上会出现「登机」之类的按钮；右上角暂停。进了机甲，按钮换成火箭 / 冲刺 / 重拳 / 核心 / 装填 / 离舱（长按）。界面里所有「按 X 键」的提示在触屏上都换成了按钮的叫法。
- **界面缩放**：HUD 和菜单按屏幕高度整体缩小（手机横屏只有 360–430 个 CSS 像素高），准星和触屏按钮不缩；生命 / 弹药收成底部中间的两条，给两侧拇指让位；刘海和底部横条的安全边距已让出。
- **性能档位**：触屏设备默认「低」画质，起始渲染分辨率再低一档（动态分辨率最低可降到 0.5），贴图边长减半（颜色 / 法线 1024，其余 512）以省显存。设置里可以改回中 / 高。切到后台会自动暂停并停掉声音。
- **PWA**：有应用清单（`manifest.webmanifest`：全屏、横屏、图标）和离线缓存（`sw.js`）。安卓 Chrome / 桌面 Chrome / Edge 在主菜单会出现「安装为应用（可离线）」按钮；iPhone / iPad 用 Safari 的「分享 → 添加到主屏幕」（菜单里的同一个按钮会显示这句说明）。进到主菜单后，后台会把首次载入用到的 51 个素材（约 12.6 MB）缓存齐，页脚出现「已缓存，可离线运行」之后断网也能打开。
  - 页面先走网络、3.5 秒内没回来才用缓存，所以重新部署后联网打开就是新版；素材按「路径 + 内容指纹」缓存，内容没变的素材不会重新下载。
  - 离线缓存只在打包后的版本（`dist/`、线上）里启用，开发服务器不注册；网址加 `?nosw` 可以不注册。
- **调试**：电脑上在网址后加 `?touch=1` 强制触屏界面（鼠标可以点按钮），再配合浏览器的设备仿真看竖屏旋转；`?nofs` 不进全屏。
- **还没在真机上验证**：以上是在桌面 Chrome 的手机仿真（真实触摸事件、竖屏 / 横屏、断网启动）里测的。真机的帧率、发热、iOS Safari 的兼容性、手感（灵敏度、按钮位置）都还没有实测。

## 首次载入的体积

第一次打开要下载的素材从 59 MB 压到 12.6 MB（页面本身经 CDN 压缩后约 0.4 MB）。模型和天空是无损的；贴图是有损重编码，正常距离看不出差别，贴近墙面、地面细看会略糊：

| 素材 | 原来 | 现在 | 做法 |
| --- | --- | --- | --- |
| 实拍贴图（44 张） | 41.9 MB JPEG | 5.5 MB AVIF | 重编码，有损（见下） |
| 模型（6 个 GLB） | 12.1 MB | 5.3 MB | gzip，浏览器端解压，无损 |
| 天空 HDRI | 5.3 MB | 1.8 MB | RGBE 分平面 + 去相关 + 水平差分后 gzip，无损（解出来逐字节一致） |

- **贴图质量档**：采用的是漫反射 q48、法线 q62 且 4:4:4、ARM q48（贴图共 5.5 MB）。`tools/tex_ab.js` 在同一会话、同一冻结画面里把贴图换成另一套，逐像素比较渲染结果（原图对原图的噪声底为 0）：这一档街景等正常距离的画面 47–57 dB，看不出差别；贴近看是 34–42 dB——地面细颗粒变少，木纹被抹平，灰泥墙上有块状不均（对比图见 `preview/贴图压缩对比-*`）。想要近景也基本无损，用 `python3 tools/pack_textures.py --q 70,80,70`（12.5 MB，贴墙近景 40–48 dB，差值是无结构的细颗粒噪声）；再往上加码收益不大（14.3 MB 时 41–48 dB，18.7 MB 时 43–49 dB）。
- **后备**：每份压缩版旁边都留着原文件。浏览器不支持 AVIF（先解一张内嵌小图探测）就取 JPEG；不支持 `DecompressionStream` 就取原始 `.glb` / `.hdr`。网址加 `?jpg` 可以强制用 JPEG 原图做对比。
- **流程**：贴图的 AVIF 由 `tools/pack_textures.py` 生成并放在 `assets/tex/`（换了贴图要重跑）；模型和天空的 `.gz` 由 `npm run build` 生成在 `dist/` 里，开发目录下没有压缩版，自动走原文件。载入逻辑在 `src/core/pack.js`。

## 部署到 Cloudflare

线上地址：<https://khamsin.dsxzai.com>。纯静态站点，用的是 Workers 静态资源，内容就是 `dist/`（本地用的 `serve.mjs` 和启动脚本由 `dist/.assetsignore` 排除）。

- 重新部署：`npm run deploy`（先打包，再 `npx wrangler deploy`；需要先 `npx wrangler login`）。
- 配置在 `wrangler.jsonc`：项目名 `khamsin`，自定义域名在 `routes` 那一行，换域名改这一行再部署即可（域名要在同一个 Cloudflare 账号下）。
- 部署内容里带着 `manifest.webmanifest` 和 `sw.js`（离线缓存）。重新部署后用户联网打开即是新版，不需要清缓存。
- 本机设了代理（`http_proxy` / `https_proxy`）时，上传那几十 MB 素材可能卡住不动；去掉代理变量直连再跑：`env -u http_proxy -u https_proxy -u all_proxy npx wrangler deploy`。

## 关于这份拷贝（总仓库说明）

这个文件夹是 KHAMSIN 收进总仓库的**精简拷贝**：只放了源码、文档和小配置（代码、脚本、网页、样式、json、md 等，单个文件不超过 1 MB）。贴图、天空图、模型、地形数据、截图、视频都没放进来，所以**直接 clone 下来不能按原样完整运行**。

好在这款游戏缺素材时会自己退回程序化的版本（见上面开头那几条）：贴图和天空退回程序化的，枪、机甲、士兵退回程序化模型，所以主地图大体能进、能玩，只是画面会明显比线上版简陋。「风歇驿堡」要读 `assets/maps/yard.kmap`，这里没有，进不去。想看完整效果，直接打开上面「部署到 Cloudflare」一节里的线上地址。
