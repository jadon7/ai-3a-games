# COD 风格枪战画面：制作记录

**成片：** 20 秒，1920×1080，30fps。场景是一座城市商场，玩家依次击杀 4 名敌人，最后换弹。

**全部是“古法手搓”：**
- 没有用 AI 生视频，也没有用任何游戏录屏。
- 画面全部在 Blender 里逐帧渲染（Cycles 路径追踪，Metal GPU）。
- HUD 和音效全部用代码从零生成。
- AI 只参与了一件事：用 Tripo 生成 4 个 3D 模型（2 个敌人、1 个玩家、1 把步枪），然后用 Tripo 的接口自动绑骨骼、套动捕动作。

---

## 1. 流程总览

| 阶段 | 做了什么 | 工具 |
|---|---|---|
| 场景 | 用 Python 脚本搭出两层回廊商场：中庭天窗、钢梁、玻璃护栏、扶梯、天桥，32 间店铺（每间都有内部陈设和灯光） | Blender 5.2 + Python |
| 材质 | 大理石地砖（抛光清漆层加污渍）、白色抹灰墙、不锈钢、玻璃，都是照片扫描贴图 | Poly Haven（CC0） |
| 道具 | 绿植、长椅、咖啡车、垃圾桶、纸箱、路障、监控摄像头等 21 种道具；地上散落 260 张纸片和碎玻璃 | Poly Haven（CC0） |
| 灯光 | 阳光从天窗斜射进来，城市 HDRI 天空，回廊下 90 多盏筒灯（约 12% 故意设成坏的），店铺暖光，空气里有灰尘体积雾 | Cycles |
| 角色 | 文字生成 3D 模型，再自动绑骨骼（Mixamo 骨架）、套“跑动 / 跪射 / 倒地”等动捕动作 | Tripo API |
| 第一人称武器 | 步枪挂在摄像机上。玩家手臂用 IK 握住握把和护木，手指逐节弯曲。红点镜删掉不透明的镜片，换成玻璃，加上全息“圈点”准星 | Blender IK |
| 敌人持枪 | 枪固定在敌人胸口，双手用 IK 握枪。中弹时松手，枪自由落地，动作切换到倒地 | NLA 动画混合 |
| 镜头 | 走路晃动、开镜缩放（18→34mm）、每发子弹的后坐力、转身时的武器惯性摆动、被射击时的镜头抖动、运动模糊 | Python 逐帧关键帧 |
| 特效 | 枪口火光（带闪光照明）、抛壳（按真实抛物线飞行）、血雾、弹孔、墙面粉尘、火花 | Blender |
| 后期 | 泛光、色差、暗角、锐化、胶片颗粒、调色，叠加原创 HUD | Python（OpenCV + PIL） |
| 音效 | 枪声、远处敌人枪声、子弹破空声、弹壳落地、脚步、开镜摩擦声、换弹机械声、命中和击杀提示音、商场底噪和远处火警铃，最后过商场大空间混响 | Python 合成（numpy/scipy） |

## 2. 剧本时间线（30fps）

| 时间 | 事件 |
|---|---|
| 0–3 秒 | 玩家沿左侧柱廊前进，阳光透过天窗打在地上 |
| 3–4.6 秒 | 敌人 1 从右侧“ATLAS SPORT”店冲出来，玩家开镜点射，击杀 |
| 6–8 秒 | 敌人 2 在二楼天桥上横穿，玩家抬枪，双杀 |
| 9.5–11.4 秒 | 敌人 3 蹲在报亭旁朝玩家开火，子弹打在身边；玩家反击，三杀 |
| 14.4–15.5 秒 | 敌人 4 从左侧“HALCYON”店冲出来，近距离腰射，四杀 |
| 16.8–18.7 秒 | 换弹：左手去拍弹匣，装填 |

## 3. 遇到的坑（可以拿来做视频素材）

1. **Tripo 连不上：** 电脑开着系统代理，访问 Tripo 接口时 TLS 握手会卡住。绕过代理直连就好了。
2. **模型被归一化：** Tripo 绑骨后的角色都被缩放成 1 米高，并且侧着朝向 ±X。改成用两边肩膀的位置自动算出朝向。
3. **步枪竖起来了：** glTF 导入的物体默认是四元数旋转模式，给欧拉角赋值不生效。
4. **红点镜不透明：** 生成的模型镜片是实心的，开镜后什么都看不见。用贴图颜色识别出橙色镜片的面片删掉，换成玻璃；前准星正好挡在红点上，也一起删了（相当于把前准星折叠起来）。
5. **开枪时画面发雾：** 枪口闪光灯照亮了体积雾。关掉这盏灯对体积雾的影响，再用灯光链接把步枪排除在照明之外，瞄具就不再发白。
6. **火光被运动模糊吃掉：** 单帧闪光在快门时间里被插值成了 0。改成在开火帧前后各半帧打关键帧。
7. **敌人瞄不准：** Tripo 的原地跑动画里，髋部比骨架原点靠前 0.9 米，按偏移量做了补偿。
8. **复制的敌人共享动画：** 复制网格时会连带共享显隐关键帧，结果敌人提前现身，需要清空复制体的动画数据。

## 4. 素材来源与版权

- **Poly Haven：** 贴图、HDRI 和道具模型，都是 CC0 协议，可以商用，不需要署名。
- **Tripo：** 角色和步枪模型用你自己的 API Key 生成，归你所有。
- **原创部分：** 商场建筑、店铺名、HUD 和音效都是原创。没有使用《使命召唤》的商标、界面、角色、地图或音效，只是“COD 风格”。

## 5. 一些数字

- **总耗时：** 约 5 小时（10:04 开工，15:03 出片）。
  - 搭建和调试约 1 小时 10 分钟。
  - 正式渲染 3 小时 40 分钟：600 帧，平均每帧约 22 秒，M3 Max 40 核 GPU，64 采样，开运动模糊和体积雾。
  - 后期合成约 5 分钟。
- **Tripo 调用：** 生成 4 个模型，绑骨 3 次，动作重定向 4 次。
- **场景规模：** 约 1,500 个物体，枪模约 100 万面，敌人 A 减面到约 14 万面。

# 第二部分：做成可以玩的游戏《商场突袭》

**目标：** 用同一套场景和素材，做一个能在浏览器里实时玩的第一人称射击游戏，画面要达到视频的水准。

**结果：** 游戏在 `game/` 文件夹，双击 `启动游戏.command` 就能玩。四组和视频同机位的对比见 `process/游戏vs视频_同机位对比.jpg`。视频每帧要离线渲染约 22 秒，游戏是每秒 60 帧的实时渲染。

## 1. 思路：贵的计算交给 Cycles，实时部分只做必须实时的

| 画面要素 | 视频里怎么来的 | 游戏里怎么做 |
|---|---|---|
| 商场的光照（阳光、钢梁投影、筒灯光斑、反弹光） | Cycles 路径追踪 | 同一个 Cycles 场景烘焙成光照贴图：4 张图集加 2 组顶点光照，共约 3,000 万个采样点，每点 512 次采样 |
| 敌人、步枪、手臂的光照 | Cycles | 在商场里放 92 个光照探针（Cycles 渲染的全景图），转成球谐光照和反射贴图，再叠加一盏带阴影的实时阳光 |
| 抛光大理石地面 | Cycles 光线反射 | 实时平面反射，再按粗糙度做模糊，涂层和底层分两层 |
| 空气里的光柱 | Cycles 体积雾 | 实时体积雾，逐像素沿视线步进 36 次，并采样阳光阴影图 |
| 色彩 | Blender AgX + Medium High Contrast，曝光 -0.3 | 把 Blender 的色彩变换原样烘成 3D LUT |
| 后期 | composite.py（泛光、色差、锐化、调色、暗角、颗粒） | 同样的参数改写成着色器 |
| HUD、音效 | composite.py、audio.py | 原样移植到 Canvas 和 WebAudio |

## 2. 流程

1. `game_prep.py`：展开道具实例，按材质拆分，生成贴图 UV。从 2,626 个可能的玩家视点做射线检测，删掉永远看不见的面（约 8,900 个）。合并成 6 个烘焙区域，展开光照 UV。
2. `game_bake.py`：Cycles 在 GPU 上烘焙，每个区域烘两遍：全部光照一遍、只有阳光直射一遍。阳光那一遍存进 alpha 通道，敌人挡住阳光时，就从地面光照里减掉这一部分，地上就有了人影。
3. `game_denoise.py`：用阳光通道引导的双边滤波降噪，保住阴影边缘。
4. `game_probes.py`：渲染 92 个光照探针（256×128 全景图），计算三阶球谐系数。
5. `game_export.py` / `game_chars.py` / `game_viewmodel.py`：导出场景、敌人（8 套动捕动作）、低模敌方步枪、第一人称手臂和步枪。换弹动作由 IK 烘成骨骼动画。
6. `game_lut.py`：把 Blender 的 AgX 色彩变换烘成 48³ 的 LUT。
7. 游戏代码在 `game/src/`，共约 3,800 行（three.js r187）：
   - `render.js`：渲染管线
   - `materials.js`：光照贴图材质
   - `player.js`：移动和武器
   - `enemies.js`：AI、寻路、双手 IK 持枪
   - `effects.js`：特效
   - `hud.js`、`sfx.js`

## 3. 遇到的坑

1. **亮度单位：** Cycles 烘焙出的“漫反射光照”乘上颜色就是最终亮度，不用再除以 π。我一开始改错过一次，后来用一张纯白材质的 Cycles 测试图逐像素对上了。
2. **光照贴图上下颠倒：** glTF 导出的 UV 和 EXR 读入方向相反，需要翻转 V。
3. **墙面一片死白：** 多材质模型导入后会拆成 `CH_arch_1` 这样的子网格，区域名识别错误，墙面拿到了默认值 16 的顶点光照。
4. **吊顶比视频暗三倍：** 一度怀疑是烘焙算错。最后发现视频的镜头脚本另外把吊顶换成了 0.86 的浅色材质，雾也加浓到 0.0055，游戏按视频的版本重新烘焙。
5. **天空转反：** Blender 的环境贴图映射和 three.js 差 180°，按 Cycles 的公式重写。
6. **枪身漆黑：** 金属材质没有环境反射就是黑的，给枪和敌人按所在位置挂上最近探针生成的反射贴图。
7. **内置浏览器抓不到天空贴图：** 它会拦截 `image/*` 类型的文件请求，本地服务器改用 `application/octet-stream`。
8. **自动截图：** 浏览器面板隐藏时页面停止渲染，改用无界面 Chrome（Metal 加速）截取对比图，并跑自动对战测试。

## 4. 验证

- 和视频同机位逐像素对比：地面、墙面、柱子的亮度差在 10% 以内。
- 自动对战测试（测试机器人自动瞄准开火）：
  - 30 秒无报错，1080p 平均 57 帧。
  - 第二轮强制触发换弹和阵亡，换弹、阵亡、复活、击杀信息都正常。
- 音效没有试听过，只核对了波形和响度，和视频的混音对齐。

## 5. 数字

- 游戏文件夹约 264MB：场景 80MB，光照贴图 86MB，武器 19MB，探针 10MB，音效 7MB。
- 光照烘焙：第一版约 17 分钟。按视频场景修正后又重烘了一次，约 16 分钟。
- 内部渲染分辨率上限约 210 万像素（1080p 级别），全屏时由浏览器放大，保证 60 帧。
